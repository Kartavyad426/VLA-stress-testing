# Retraining visualisation

This is the default output format for retraining work: one self-contained HTML page per study, generated by scripts. **Do not hand-write charts.** Edit the config, run the build, and check the result.

## Run it

```bash
# from the repo root, CPU only, stdlib python
python3 .claude/skills/retraining-viz/scripts/build.py \
    --config .claude/skills/retraining-viz/scripts/configs/start_pose_pilot.json \
    --out docs/RETRAINING_VIZ.html \
    [--read-rollouts] [--compare docs/RETRAINING_VIZ.html]
```

- `--read-rollouts` lets the one panel that needs `rollouts.jsonl` (achieved t = 0 gripper offset) read it. It is **off by default** (see the metadata-only rule).
- `--compare FILE` diffs the new page's embedded data blob against an existing page and prints each difference as `path: old -> new`. Exit code 1 means they differ. Use it to confirm a refactor or config change altered only what you meant to change.
- The build prints every skipped panel and its reason. The page shows the same list at the top and a skip note in place of each missing chart.

## Adding a run

Add entries to the config (or copy it into a new config for a new study) and re-run. The template contains no run names, so no template edits are ever needed.

| Config block | One entry per | Fields |
|---|---|---|
| `arms` | colour / legend identity | `n` label, `c` colour token `--base` or `--s1`…`--s8` (assign slots in order, never reuse) |
| `train_runs` | training run | `key`, `arm`, `title`, `row`, `arm_label`, `log`, `accum`, `log_format` (`"cached"` for cached-feature runs), `report`, `lr_trace_from_report`, `inventory` (`"report"` or `"ckpt_meta"`), `ckpt_dir`, `eval`, `overlay`, `status`; optional `curve_json`/`curve_blob_key`, `gate`, `short`, `no_grad`, `kind: "smoke"` |
| `failed_runs` | run that died before logging loss | `key`, `log`, `total_micro`, `planned`, `note` |
| `evals` | eval directory with `score.json` | `dir`, `arm`, optional `base_arm`, `wise_arm` |
| `diag` | diagnostic outputs | `loss_summary`, `fit`, `fit_rows`, `offset_curve`, `models` (model name → `{arm, step}`) |
| `data` | training dataset | `dataset`, `datasets`, `mint_manifest`, `yield`, `coverage`, `mix_run` |
| `manifest_counts`, `val_extra`, `upstream`, `extra_sources` | as in the default config | |

Then:
1. Run the build (add `--compare` against the previous page to see exactly what changed).
2. Render it headless and look at it: `google-chrome --headless=new --screenshot=… --window-size=1280,16000 file://…`. Check for console errors and for label collisions.
3. Hand the path to the session that commits. This skill never commits.

## Panels and the inputs each needs

Each panel is a function in `scripts/extract.py` that reads only the files named in the config. A missing file raises `Missing`, and the panel is skipped with a visible note. **Nothing is ever filled in or guessed.**

| Panel (function) | Reads | Draws |
|---|---|---|
| `panel_loss` | `train_runs[].log` (lerobot or `[cached]` format); `report → lr_trace.applied` | loss curves, LR, grad norm, overlay |
| `panel_failed_runs` | `failed_runs[].log` | OOM / failed-run tiles |
| `panel_curves` | `train_runs[].curve_json` (`eval[]`, `train[]`) | train-time fixed-seed eval curve |
| `panel_gates` | `gates` (R-055 style `gates.json`) | gate table, overfit endpoints |
| `panel_smoke` | smoke `report` (`eval_loss_step0/final`) | smoke tiles |
| `panel_inventory` | `*_train_report.json`; `checkpoints/*/pretrained_model/vla_train_meta.json` (`opt_step`, `micro_step`) | inventory table, checkpoint markers |
| `panel_manifest_counts` | `<dir>/manifest.jsonl` | (ckpt, set) counts, e.g. val-only runs |
| `panel_score` | `<eval>/score.json` | validation per checkpoint (`selected.all`), held-out and nominal Wilson, per band, McNemar, expectations, WiSE |
| `panel_per_rollout` | `<eval>/manifest.jsonl`; with `--read-rollouts` also `rollouts.jsonl` and `nominal_starts` | per-scene table; achieved-offset chart |
| `panel_transfer` | `<eval>/transfer/rows.jsonl` | W per transfer instance |
| `panel_d20` | `diag.*` (`loss_summary.json`, `fit_firstchunk.json`, `fit_firstchunk_rows.jsonl`, `r047_offset_curve.json`) | loss per subset and per checkpoint, fit test, offset curve |
| `panel_data` | `data.dataset/meta/{provenance.jsonl,export.json}`, `*/meta/info.json`, mint manifest, `yield.json`, `postmortem_coverage.json` | data distribution |
| `panel_upstream` | `upstream.r053`, `upstream.r057` score files | context tables |

## Rules the scripts encode (do not undo them)

- **Loss logging cadence.** lerobot_train logs `loss:` every 10 **micro**-steps, and the value is the mean of those 10 micro-batches (`AverageMeter`, reset at each log: `third_party/lerobot/src/lerobot/scripts/lerobot_train.py:698,792`). With accumulation 8, that is one point every **1.25 optimizer steps**. Take the micro-step from the tqdm counter `N/TOTAL`, because the `step:1K` field is rounded. Cached-feature runs print `[cached] opt step N loss X` every 10 optimizer steps, as the mean of the last accumulation × 10 micro-batches (`experiments/r056_train.py:478`). Read block medians, not single points.
- **Metadata-only.** The build reads reports, `score.json`, `selection.json`, `manifest.jsonl`, `vla_train_meta.json`, logs and diagnostic JSONs. It **never reads `rollouts.jsonl` or `.npz` unless asked** (`--read-rollouts` or `"read_rollouts": true`). When it is asked, the offset split is asserted equal to `score.json → exploratory_gripper_offset` at build time.
- **Joins.** Manifest line *i* is joined to rollout line *i*, and start keys (scene, dir_seed, radius, noise_seed, env_seed) are checked unique. `rollout_id` ignores the noise seed, so it is only asserted equal, never used as a key.
- **Statistics are not recomputed.** Wilson intervals, McNemar b/c/p and `gap_closed` are read from `score.json` (written by the eval scorer, `experiments/r056_eval.py`), so nothing here duplicates `vla_harness.runner.wilson_ci`/`mcnemar` or `experiments/stats.py`. The page computes only block medians, pooled mean ± SE across D20 subsets, per-scene and per-offset counts, and sampler draws per frame. Each of these is labelled "computed" where it is shown.
- **Visualisation only.** The page carries no interpretation. Analysis belongs to `finetune-postmortem`.
- **Output.** One standalone HTML file with inline JS, embedded JSON (`#vizdata` holds the data and `#vizmeta` the labels, sources and skips) and no external scripts. It supports light and dark themes and works at phone width. It is a local file in `docs/`, never a published artifact.

## Files

- `scripts/build.py`: the entry point. It runs the panels, builds the inventory and gate rows, the source captions and the Sources list (flagging any path missing on disk), writes the HTML, and handles `--compare`.
- `scripts/extract.py`: one function per panel, the log parsers, and `Missing`.
- `scripts/template.html`: the CSS, the chart library (xy, bar and dot-CI charts with hover tooltips) and the config-driven renderer.
- `scripts/configs/start_pose_pilot.json`: R-053 to R-058. With `--read-rollouts`, it reproduces the committed `docs/RETRAINING_VIZ.html` data blob exactly.
