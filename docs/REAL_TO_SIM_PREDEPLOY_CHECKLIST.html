Real-to-sim: checklist before deploying a policy

res31, 10-15, internal. Run every check on every scene before trusting a VLA rollout in it. Sources: the user's checks (interaction, gravity, scripted expert) plus res31's (geometry, cameras, interface, policy sanity). Status columns hold only what has been measured; not run means unknown, not passed. Exploratory, numbers UNVERIFIED until val checks the code.

Why this list exists (10-15 finding). GR00T-N1.7-DROID's smoke test on ep_orange_block reached the right block and hovered without closing. Measured: during the hover it commands the fingertip point 4.5 cm below our table top (achieved: about 1 cm into it, blocked by the table; 3.5 cm sustained tracking error in z). The real operator's own grasp in this episode puts the same fingertip point 5.0 cm below our block centre (horizontal error only 0.7 cm). Both point the same way: relative to the robot, our table and objects sit about 4–5 cm too high (or our gripper is about that much too long; not yet separated). c3 shows the same size of error (recorded grasps a median 5.1 cm below the rebuilt cart top). The scripted expert never sees it because it reads the sim's own object positions. Checks 3 and 17 would have caught it before any GPU run.

E. Counting rule

A rollout failure counts as a policy failure only if: the expert solves that variant (2); the scene passes A3, A6/A7 and C17 (no sustained blocked command); and D19–D20 show the policy behaves on real frames and our visuals barely change its actions. Anything else is unattributed.
