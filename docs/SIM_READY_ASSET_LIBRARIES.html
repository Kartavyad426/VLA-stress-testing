Sim-ready 3D asset libraries for real-to-sim retrieval

2026-10-14 · session res32, brief from res31 (user-approved 10-14) · outline approved by the user 10-14, option (c): docs only · companion to REAL_TO_SIM_SCENES.html and REAL_TO_SIM_ASSETS.html

Status: desk research only. Nothing has been downloaded and no code has been run. [V] means I read the claim in the library's own page, dataset card, licence file, README or paper (linked in §9). [I] means I inferred it. not checked means I could not find it in a source, and it is left out of the recommendation. Collision quality is taken from what the docs say. Measuring it (watertight or not, number of parts) is the follow-up the user parked as option (a).

1 · Verdict

Kitchen/household: four libraries are permissively licensed (CC BY 4.0) and need little or no conversion. (1) NVIDIA/Lightwheel Kitchen-MJCF: native MuJoCo, decomposed collision meshes, 58 object types plus 17 fixture groups, 1.32 GB [V]. (2) mujoco_scanned_objects: all 1,030 Google Scanned Objects as MJCF with 32 V-HACD convex parts each [V]. (3) YCB: 80+ objects, CC BY 4.0; needs obj2mjcf + CoACD [V]. (4) RoboCasa assets: MJCF, CC BY 4.0 as stated by RoboCasa, about 10 GB [V]. For articulated kitchen objects, Infinigen-Sim (BSD-3 code) generates MJCF for 18 categories on the CPU, so there is nothing to download [V].

Industrial: there is no open, permissively licensed, sim-ready library of bins, totes, tools or fasteners that I could verify. The best checked options are T-LESS (30 industrial parts, CAD models, CC BY 4.0) [V] and NVIDIA SimReady Warehouse-01 (753 USD assets with colliders, CC BY 4.0, ~15 GB). Warehouse-01's visible rows are mostly hand-sized props, not totes or bins [V]. ITODD, IPD, XYZ-IBD, Fusion 360 Gallery and PartNet-Mobility are non-commercial [V]. ARMBench has no 3D models [V]. For bins, totes and boxes, building them from MuJoCo box primitives is likely cheaper than any library [I].

Licence finding on what we already have. The LIBERO-Plus new_objects folders use BEHAVIOR-1K's file layout, including *.encrypted.usd files [V]. The BEHAVIOR Data Bundle EULA allows non-commercial academic research only, use only within OmniGibson, and no redistribution [V]. If these objects do come from BEHAVIOR [I], most of our 1,176 models (all but the LIBERO originals) cannot be used in a commercial product. Details in §4.

Retrieval index: no checked kitchen library above ships image embeddings. Objathor/Holodeck annotated about 50K Objaverse assets with category, size in cm, mass and material, and retrieves them with CLIP [V], but the asset licences are mixed per object (§3a). We will have to build our own CLIP/DINO index over whichever library we adopt [I].

2 · What "sim-ready" means here

Our pipeline is detect → retrieve a mesh → place → simulate, in MuJoCo. A retrieved asset is useful only if it already has, or cheaply gets, each of these:

CriterionWhy it matters for usCheapest fix if missing
Collision geometry (convex parts)MuJoCo convexifies each mesh geom for collision [V], so a raw concave mesh (bowl, mug) collides as its convex hull.CoACD or V-HACD → convex parts (§5)
Watertight meshNeeded for a correct volume, so mass and inertia from density come out right [I]Repair, or accept approximate inertia
Real-world (metric) scaleThe gripper and arm are real size. A wrong scale breaks grasp width and height.Rescale from the detector's metric depth, or from an annotated size
Mass / frictionCan't be seen. Matters for pushing, sliding and heavy objects.Density priors per material; randomise
JointsDrawers, doors, lids, appliancesOnly from an articulated dataset or a generator
Native formatMJCF is ready to use. URDF loads into MuJoCo directly. OBJ/GLB needs obj2mjcf. USD import in MuJoCo is experimental [V].§5
Retrieval indexImage → asset lookupRender thumbnails and embed them ourselves
LicenceThe work may become a product (BRAINSTORM offerings), so non-commercial licences block it.None

Writing it would be code, so it needs a go.

4 · Overlap with what we already have

Our LIBERO-Plus objects appear to be BEHAVIOR-1K assets, and BEHAVIOR's EULA is non-commercial.

  • Each object in third_party/LIBERO-plus/libero/libero/assets/new_objects/<category>/<6-letter id>/ has misc/metadata.json and usd/<id>.encrypted.usd next to a plain <id>.usd and an MJCF folder [V] (checked on disk, e.g. apple/agveuv).
  • OmniGibson's own loader rewrites asset paths from .usd to .encrypted.usd (asset_utils.py lines 307, 333) [V]. The metadata uses BEHAVIOR-style category/model IDs (e.g. "category": "half_apple", "model": "sguztn") [V].
  • BEHAVIOR Data Bundle EULA (rev. 2022-12-08), terms 2–5: "Data may only be used for non-commercial academic research"; "strictly prohibited from extracting any Data from OmniGibson or reverse engineering"; "may only use the Data within OmniGibson"; "may not redistribute … in whole or part" [V].
  • The LIBERO-Plus README and the asset folder state no licence or provenance [V]. That these objects are BEHAVIOR's is my inference from the matching layout [I]. Confirming it means asking the LIBERO-Plus authors.

Consequence: REAL_TO_SIM_ASSETS.html already says "check before any commercial use". This makes it concrete. For anything that could become a product, treat the LIBERO-Plus new_objects (and probably its other non-LIBERO folders) as research-only. That leaves the LIBERO originals (HOPE, scanned and TurboSquid objects, already in the LIBERO repo), whose licence is still not checked. That page is owned by res31; I have not edited it.

Where the new libraries add coverage: GSO (1,030) and YCB (80+) are scanned real products, closer to what a camera sees than LIBERO-Plus's artist models [I]. Kitchen-MJCF adds utensils and appliances (colander, grater, peeler, pizza cutter, blender, coffee machine, kettle) that our library's keyword list mostly lacks [I]. Overlap by category has not been computed; that needs a script.

Conversion effort per format [I]: MJCF is ready to use. URDF is a single load-and-save, with joint and inertia values to check by hand. OBJ/GLB needs obj2mjcf + CoACD + a scale and density guess per object. USD has an experimental path; for SimReady Warehouse, exporting meshes to OBJ and running obj2mjcf is probably safer. CAD (STEP) needs tessellation first, then CoACD.

6 · Recommendation

Built from [V] claims only; the reasoning that connects them is mine [I].

  1. Kitchen, rigid: start with Kitchen-MJCF (native MJCF, decomposed collision, CC BY 4.0, utensils our library lacks) and mujoco_scanned_objects (1,030 real scans, 32 convex parts each, CC BY 4.0 / MIT). Neither needs conversion.
  2. Kitchen, more breadth: YCB (CC BY 4.0) via obj2mjcf + CoACD, then RoboCasa (MJCF, ~10 GB; filter out any Objaverse-sourced objects with NC per-object licences).
  3. Kitchen, articulated: Infinigen-Sim: CPU generation, MJCF export, CoACD hulls, joint dynamics. Avoid PartNet-Mobility, PhysX-Mobility and PhysXNet for anything commercial.
  4. Retrieval: build our own embedding index (render thumbnails → CLIP/DINO) over the adopted libraries. Holodeck shows CLIP + size matching works for this [V]. Objaverse with the Objaverse++ quality filter and a CC BY / CC0 licence filter is the long-tail fallback, at the cost of per-object conversion.
  5. Industrial: T-LESS (CC BY 4.0) for machine-part-like objects. SimReady Warehouse-01 only after a USD → MJCF test, since its contents look like props rather than logistics items. Build bins, totes and boxes from primitives. Treat ABC as unclear until someone reads Onshape ToU 1.g.ii.
  6. Existing library: mark the LIBERO-Plus objects research-only until their provenance is confirmed (§4).
