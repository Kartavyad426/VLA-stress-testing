3 · Root logic

3.1 · Why the toy's rule isn't enough (UQ10)

The toy took the root to be "the first grasp onset that fails the lift test". prim's CPU probe applied six draft event rules to all 720 R-047 rollouts and kept every event. I re-ran it read-only on 10-09 and got identical output. That reproduces the numbers but is not an independent check: it is the same code. UNVERIFIED (probe at prim's scratchpad root_rules_probe_v2.py, not val-checked).

FindingNumbers (of 176 failures, 544 successes)
Most failures fire several modesDistinct modes per failure: 1 → 61, 2 → 90, 3 → 20, 4 → 4, 5 → 1. Top combinations: miss + wrong_object 50, miss + drop 19, miss + slip 17.
The rule for picking the root changes the labelFirst in time: miss 99, drop 30, slip 23, wrong_object 20, wrong_location 3, stall 1. Fixed precedence: miss 95, wrong_object 68, slip 10, wrong_location 1, stall 1, drop 1. The two disagree on 83 / 176.
Rules fire inside successes163 / 544 successes fire at least one event. Some are real recovered events. Some are rule bugs: drop fires on placing, and wrong_object fires on bumps.

The repo has hit the same problem before V:

  • classify.py moved from first-match-wins to "evaluate all rules", because 76.6% of LIBERO failures matched more than one rule (R-008).
  • _attempt_spread was added after precedence masked a manipulation fault as "recovery".
  • O4: an OR hid two broken holding detectors.
  • UQ7: "first failing grasp" skips a grasp-then-drop.

v1 therefore keeps every event, decides the root with an explicit, configurable rule, and stores the alternatives next to it.

3.2 · Event vocabulary (v1)

Each event is (t, phase, mode, measures). Failure events are the modes below. Success events mark a phase completed; they are needed for the recovered flag. All thresholds are in §6.

3.3 · The recovered flag N2

  • R1, phase-local (recommended). A failure event is recovered if a success event that completes its phase happens later in the episode:
    • grasp.* is recovered by a later grasp.ok;
    • transport.drop and place.off_target are recovered by a later place.ok.
    The flag stores recovered_by_t and cost_steps = recovered_by_t − t.
  • R2, episode-level. An event is recovered only if the episode succeeds. In a failure nothing is recovered, so option (a) collapses into (b). Simple, but it throws away the information we want.

Invariant under R1: a successful episode has no unrecovered failure event. If one appears, that is a rule bug, which makes it a free check on all 544 successes (§4, events, check plan).

3.4 · Root options N1

Root isForAgainst
(a) recommendedThe first unrecovered failure event (R1)It names the event the episode never got past, which is where the success data has to come from. Order-independent: no precedence table.A recovered event that burned most of the time budget is not called the root, although it may be why the episode ran out of time (§3.5).

Whatever is chosen, every instance stores the root under all five options (root_alternatives), so the choice can be revisited without re-running anything. Only the designated root sets the instance's identity (index id).

3.6 · Recovery instances N3

A recovered failure event in any episode, success or failure, becomes a type: "recovery" instance. Its situation is taken at the event, its success segment runs from the event to recovered_by_t, and its terminal is the episode's outcome. These are the policy's own successes from a bad situation: mining targets that need no new data collection. They also feed the search pool, as "our successes from situation X". Cost: a field and a filter in ms_v1_build_spec.py, about 0.25 d.

3.7 · The in-gripper check (wrong_object, grasp.ok, drop)

An object is in the gripper over a window [t, t+K] when all three hold:

  1. Its distance to the grip site is ≤ GRIP_R at every step.
  2. Its displacement follows the eef's: ‖Δobj − Δeef‖ ≤ FOLLOW_M per step, on average over the window.
  3. The gripper is commanded closed.

A bump moves an object without it following the eef. A lift follows. Uses only _gt_scene_object_pos and eef_pos for rollouts, and restored states for demos.

GRIP_R, FOLLOW_M and K are placeholder, then fit: demos: the distribution over all demo grasp.ok windows, taking the 99th percentile for distance and following error.

3.8 · Symptom and decision anchors (UQ1)

The root is a symptom anchor: where the failure shows. v1 fills only anchor.symptom = {t, event}. anchor.decision stays null with method: "not measured". Filling it needs interventions (R-044/R-057 style), which are outside v1. The doc and the spec say plainly that the root is "where it showed", not "where it was decided".

vla_harness/mining_spec/state.py

Read both pools into one frame: per-step eef, gripper rotation, aperture, object poses.

Inputs → outputs
A rollout dict from rollouts.jsonl, or a demo group in an HDF5 file → an EpisodeState: arrays eef[T,3], R[T,3,3], aperture[T], cmd_closed[T], obj[name][T,3], plus key (pool, file_or_run, row_or_demo) and success.
Logic
  1. Rollouts: read eef_pos, joint_pos, gripper_qpos and _gt_scene_object_pos per step. Compute R by forward kinematics from joint_pos in the kinematic model of the rollout's task. Assert the FK site agrees with eef_pos to ≤ 2 mm at every step. Do not use eef_quat, which is not the site frame V.
  2. Demos: load the demo's own model_file MJCF in plain MuJoCo. Remap the two author asset prefixes, deriving the robosuite root from robosuite.__file__. Fail if any asset path doesn't resolve. For each t, set qpos = states[t, 1:1+nq] and run mj_forward, then read the grip site and bodies.
  3. Demo lag check: assert ‖site(states[t+1]) − obs/ee_pos[t]‖ ≤ 1 mm for all t. That is the lag-1 fact V (toy max 0.68 mm), used as a guard.
  4. Episode key: rollouts by (run, line index), with the manifest line order asserted (same task, perturbation and success). Demos by (file, demo name). Never key on rollout_id V.
Rules
FK tolerance 2 mm toy (observed 0.5–0.6 mm). Lag tolerance 1 mm toy.
Known problems
(1) The remap is checked on one file only V; solution: fail-fast on all 10 files. (2) The toy uses task 984's model for every rollout's FK; solution: one model per task, plus the per-step assert.
Toy reuse
poc_toy_common.load_model, fk_rot, site_rot, angle_deg, tilt_deg and the restore loop in demo_events: generalised, not rewritten.
Val plan
Anchor: row 14, t=31: eef→bowl offset (−6.84, −3.63, +1.31) cm and tilt 4.1° (runs/poc_toy/instance.json), equal to relative 1e-6. Null: restore the same demo state twice → identical arrays. Planted: shift one body's qpos by 5 cm → its reported pose moves 5.000 cm and nothing else does. Invariants: FK ≤ 2 mm on all 720 rollouts; lag-1 ≤ 1 mm on all 500 demos; T matches between arrays; unique keys.
Effort
1 d

vla_harness/mining_spec/events.py

The root logic: every event, the recovered flags, the root under every option. This is the core new code.

Inputs → outputs
An EpisodeState → events: list[Event] sorted by t, each {t, phase, mode, kind: failure|success|marker, measures, recovered, recovered_by_t, cost_steps}, plus roots: {a, b, c, d, e} and unexplained_reason when a failure has no failure event.
Logic
  1. Find all grasp.onsets. With none and a failed episode, emit approach.never_reached at T−1.
  2. For each onset, run criteria.grasp_ok. Classify as grasp.ok / wrong_object / slip / miss by §3.2, checking in that order. The order is safe because the four are mutually exclusive by construction: wrong_object requires a non-target object in the gripper, ok requires the target in the gripper, and slip and miss split on lift.
  3. After each grasp.ok, track to the first of: a release command → criteria.place_ok → place.ok / place.off_target; separation while commanded closed → transport.drop; or episode end → no event (still holding at timeout; recorded in terminal).
  4. Flags (R1, N2): for each failure event, search forward for the completing success event; set recovered, recovered_by_t and cost_steps.
  5. Roots: (a) first unrecovered; (b) first failure; (c) by precedence (config); (d) last failure; (e) (a) ∪ {recovered with cost_steps ≥ COSTLY_FRAC·T_max}.
  6. Invariants raised as errors: a successful episode with an unrecovered failure; a failed episode with no failure event and no reason.
Rules
All from thresholds.json (§6). The precedence table for (c) is config only, never used as the designated root unless N1 picks it.
Known problems
(1) Multiple modes per episode (UQ10): handled by keeping all of them. (2) Drop vs place: separation test (§3.2). (3) Bumps counted as wrong_object: in-gripper test (§3.7). (4) Re-grasps from a raised rest height: base height at onset. (5) Holding at timeout: no event, terminal says so. (6) Every threshold is a placeholder or fit until the labels score it (§7).
Toy reuse
Onset detection from grasp_events. The rest is new; the probe is a reference only (UNVERIFIED, not ported).
Val plan
Anchor: row 14 onsets at t = 31, 80, 103, 128, 176, 201, 263, 272 (traces.json), and §3.5's table once N1/N2 are decided. Null: clean successes (no retries) → only marker and success events. Under R1, all 544 successes have zero unrecovered failure events. Planted, on copies of success traces:
  • hold the bowl at its onset height for 40 steps → grasp.miss at that onset;
  • mid-transport, separate the bowl and drop it 5 cm while the eef stays → transport.drop at that t;
  • move the release point 6 cm from the plate → place.off_target;
  • attach a neighbour to the eef path → grasp.wrong_object.
Invariants: events sorted; mode labels from the closed list; flags consistent with times. Plan: rules line by line against §3.2.
Effort
2.5–3 d

vla_harness/mining_spec/snapshot.py

The situation at an event: the fields a search matches on.

Inputs → outputs
(EpisodeState, event) → situation: {at_t, observation_window: "1 frame", fields: {name: {value, unit, source, sigma, held_fixed}}, frames: {agent, wrist}}. In v1 every source is exact and every held_fixed is true (mechanism unknown).
Fields
Grasp events, at onset:
  • eef→target offset (3, cm);
  • gripper rotation (quaternion in the site frame, plus tilt in degrees);
  • aperture;
  • target xyz;
  • each neighbour's xy relative to the target (4 × 2).
Place events, at lowering onset (the first step of the final descent while held: eef z velocity < −V_DESC for 3 steps) placeholder:
  • target→goal offset (3), gripper rotation, target tilt.
Drop events: the eef→target offset and eef velocity at separation.

The field extraction in poc_toy_instance.py and grasp_events (~30% of the instance builder).
Val plan

experiments/ms_v1_labels.py

Build the blind labelling sheet; later, score the rules against the labels (§7).

Command
... ms_v1_labels.py sample --n 30 --seed 0 → runs/ms_v1/labels/sample.json. ... ms_v1_labels.py sheet → labels/sheet.html (videos plus a form, no rule outputs shown) and labels/labels.csv (empty). ... ms_v1_labels.py score → labels/score.json and score.html.
Logic
Sampling is stratified (§7.2), with the seed recorded. The sheet embeds the GPU-rendered videos (ms_v1_render.py) with a frame counter. Scoring matches each labelled event to a rule event of the same mode within ±10 steps. It reports per-mode precision and recall with Wilson 95% CIs, and root agreement for each option (a)–(e).
Known problems
Sampling uses the rules' output, while the labels must not see it: the sheet hides it. A single labeller can't give inter-rater agreement: a 5-episode self-re-label is the stand-in.
Toy reuse
None.
Val plan
Planted: a synthetic label file equal to the rule output → precision = recall = 1 and agreement 100%. Shift every label by 11 steps → zero matches. Recompute: one mode's precision by hand.
Effort
1 d (plus 3–4 h labelling N4)

7 · Hand-labelling protocol

7.1 · Who N4

One labeller: the user, or a person they name. If only one person labels, they re-label 5 episodes at least a day later, in a shuffled order, as a self-consistency check.

7.2 · Which episodes (30, from R-047, stratified, seed recorded)

  • 20 failures, start-pose axis, stratified by the rules' first-in-time root: ~6 miss, 4 slip, 4 drop, 4 wrong_object, 1 place.off_target, 1 never_reached, spread over at least 6 scenes. Row 14 is always included.
  • 6 successes that fire failure events (recovered candidates): 2 with drop, 2 with miss, 2 with slip.
  • 4 clean successes, as a null.

7.3 · What the labeller sees and does

  • Agent and wrist videos side by side with a step counter, rendered on GPU through the gate N10. The episode's instruction. No rule output, no success flag.
  • For each episode the labeller lists every event as (t_start, mode from the closed list or "other: text", recovered y/n), then the root under their own judgement (the first thing that went wrong and was never fixed), a confidence of 1–3, and notes.
  • A one-page guide with one example clip per mode. Expected ~6–8 min per episode, about 3–4 h in total I.

7.4 · Scoring

A rule event matches a labelled event if the modes are equal and |Δt| ≤ 10 steps (0.5 s). The report gives:

  • per-mode precision and recall with Wilson 95% CIs;
  • root agreement for each option (a)–(e) against the labeller's root;
  • self-consistency on the 5 re-labels.

With n = 30, the CIs are wide (±15–20 points). The result is a measured order of magnitude, not a certification.

7.5 · Acceptance N5

Proposal: the designated root option needs agreement ≥ 80%, and each mode used in roots needs precision ≥ 0.8. A mode below the bar stays in the spec, marked unvalidated wherever it's quoted. A root option below the bar triggers a rule revision before v1 is called done.

7.6 · External labels: the podolinsky set N12

Added by prim, 2026-10-12, after this doc was written. Sources: the dataset card for podolinsky/groot-libero-10-features-v3 (read 10-12 V), docs/FAILURE_LABEL_DATASETS.html (res21), docs/ROOT_IDENTIFICATION.html.

What it is. 500 rollouts of NVIDIA's GR00T-N1.7-LIBERO (libero_10 checkpoint) on libero_10: 10 tasks × normal and LIBERO-Occ occluded × 25 initial states, seed 7. Each failure (169) carries a Gemini 3.5-flash failure mode (10-way), an onset type and an onset frame refined on a slowed clip. The prompts are published verbatim. Each inference stores K = 10 sampled action chunks, layer-16 backbone features and the executed actions; 115 occluded failures are occlusion-only (the paired normal episode succeeds).

What it can do for v1.

  • Audit the symptom anchor and our VLM labeller (vlm_label.py, E7) against an independent onset, using FailTime's onset rules for any hand check. A hand-labelled sample of these onsets checks Gemini and our labeller in one pass.
  • Map their 10 modes onto our phase × mode list (impl2's phase 1, item 3).
  • Give paired normal/occluded failures as extra root-rule test cases.

What it can't do, and why it doesn't change our config.

  • It is a different checkpoint, suite and execution setup (C = 16 predicted / H = 8 executed vs our C = 40 / H = 16). We use it as an external audit set; our libero_spatial configuration and every earlier result stay as they are. Running v1 itself on libero_10 would be a second configuration added next to ours, a scope change for the user to decide, not a replacement.
  • No simulator state is stored (no object poses, no raw gripper width). The v1 rules (§3) need object height and gripper state, so they can't run on it directly. Running them needs the sim state rebuilt by replaying the stored actions from the stored initial states, which is impl2's phase 2 (GPU, not approved yet), and replay fidelity is unverified.
  • The labels are VLM-made and unchecked by any human, and mark where a failure shows, not where it is decided (UQ1). No licence is stated: internal use only.
  • So the ~30-episode set on our own R-047 rollouts (§7.1–7.5) stays; v1's pass test (§7.5) is unchanged.
