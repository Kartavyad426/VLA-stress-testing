Bottom line

  • A failure has two different "roots": where it shows (the symptom, e.g. the gripper closes 6.8 cm short) and where it was decided (for start pose, by forward 0–1). Only an intervention can find the second.
  • Simple tasks (LIBERO pick-and-place, v1): find the symptom with event rules on telemetry and sim state, root = the first unrecovered event, with a VLM filling the rules' blind spots. The decision point comes from interventions, where we have them.
  • Complex tasks (cloth, pouring, drawers, long-horizon): gripper rules break; they need per-task-family phases, progress signals, the VLM, and task-agnostic signals. Still experimental.
  • Evidence so far: our draft rules are not unique per episode and their order changes 83/176 labels. The cheap policy-side timing signals only find the grasp event. So the rules need measuring against ground truth, which means hand-labelled episodes or a dataset with root labels (res21 is searching).

1 · Why root matters

The root is where a mining-spec instance hangs (D13). Everything downstream starts from it:

UseWhat the root provides
IdentityThe instance's sub-scenario = phase × failure mode at the root (D12). This is what the index and the failure corpus count.
Search keyThe success search matches a snapshot of the situation at the root (D14): the same situation, gone right.
Restore pointSim generation replays the prefix up to the root, then substitutes a successful continuation (UQ2).
Teleop brief"Get to here, then succeed."
Training weightThe frames around the root carry nearly all the new signal (R-054: only 5–13% of minted frames were new information).

Which root matters depends on the fix (UQ1). A symptom anchor asks for recovery data (succeed from the bad situation). A decision anchor asks for prevention data (don't get into it). R-056 was the prevention kind; it fitted its training starts but didn't generalise.

2 · The problem, as we understand it

  • Two anchors proposed (t10c). Toy case, scene 984, start pose 0.2 rad: the gripper closes 6.8 cm short at t = 31 (the symptom), but R-044 rescued 7/7 start-pose failures by correcting forward 0, and R-057 found start pose decided by forward 1 (the decision) [V].
  • Rules are not unique (UQ10 probe on 720 R-047 rollouts, unverified): 115/176 failures fire 2 or more failure modes (retry loops pile up events). Root = first event vs a fixed rule order disagree on 83/176. Rules also fire inside 163/544 successes: partly real recoveries, partly rule bugs (placing looked like dropping; bumps looked like wrong-object grasps).
  • "First event" can be the wrong root [V]. Row 14 slips at t = 31, then retries, then carries the bowl to the plate and releases it 5.2 cm off centre (successes end ≤ 3.0 cm). Under "first unrecovered event" its root is place × off-target at t = 242, not grasp × slip at t = 31.
  • Rule blind spots (UQ4): wrong object (a clean lift of the wrong bowl), wrong placement, never reaching or hesitating, pushing the object during the approach, collisions, fingers stalling on the table.
  • Other task families (UQ5): cloth, pouring/wiping, drawers, insertion and bimanual have no crisp gripper events; success is a shape, a flow, an angle or a force.
  • External data (§6c, D15): outside sim there are no object poses or contacts; fields must be estimated (with error) or come from a VLM.
  • Policy-side signals so far (10-09, exploratory): chunk self-consistency (E1), gap to nominal (E2), commanded vs achieved (E3) and FAST tokens (E6) either track the grasp event, which the rules already find, or reflect perturbation size. None marks where a failure was decided. Reading: R-047 failures are "smooth and wrong" [I].
  • Labels from outside the model agreed (D16): the spec's labels come from actions, telemetry, sim state, a VLM or action tokenizers. Looking inside the model is for mechanism localisation only.

3 · Proposed solution proposed

Simple tasks (v1 scope: LIBERO pick-and-place)Complex tasks (experimental)
Symptom anchorEvent rules on telemetry and sim state: grasp onset (gripper commanded closed) → miss, slip or wrong object; held then lost away from the goal → drop; released with the goal relation failing (goal threshold ≈ 3 cm, not 6) → off-target; no grasp before timeout → stall. Store all events, time-ordered, each flagged recovered or unrecovered. Root = the first unrecovered event. Recovered events in successes become a "recovery" instance type. Thresholds fitted from the 500 human demos. An explicit "unexplained deviation" class.

4 · Why we need hand-labelled data

  • There is no ground truth for the symptom anchor. Our rules, the VLM and the policy signals are all detectors; without labelled episodes we can't tell which is right when they disagree (83/176 disagreements already).
  • To measure each rule's error rate (P4b) before v1 relies on it, and to fix the loose ones: drop vs place, wrong object vs bump, and the 163/544 fires in successes.
  • To choose the root rule between first-in-time, first-unrecovered and a precedence order, using real cases like row 14.
  • To score E7 (the VLM's answers) and E5 (the combined root) against something other than another detector.
  • Why labels are valid here: symptoms are visible (UQ1), so a human watching the episode can mark them. Decision points are not visible; those come from interventions, not labels.
  • Proposed protocol open (t10b): ~30 R-047 episodes, mixed failures and successes, start pose and camera. Per episode: every event with its step, phase × mode, recovered or not, and the root. A session labels and the user checks a sample. Rendered frames may need a GPU replay (PoC's v1 item).

5 · What res21 is researching (brief, started 10-12)

Datasets, sim or real, with richer failure labels than usual, ideally root or onset time: label granularity, how labels were made, the taxonomy and its overlap with our phase × mode list, recovery annotations, size, robot and action-space fit, whether GR00T is in-domain (D10), licence. Leads to check: LIBERO-Recover, ProTracer, RoboMIND failure labels, AHA, RoboFAC, REFLECT, FailGen, Sentinel/FAIL-Detect data, AutoEval logs. It builds on res22's TASK_DIVERSITY_LANDSCAPE §6. Goal: headroom for E5 and the v1 rules, and possibly a replacement for our hand-labelled set. Deliverable: FAILURE_LABEL_DATASETS.html (done 10-12).

Result (res21, 10-12; existence, gating and licences checked by prim against the HF API):

  1. No public dataset labels the decision point. Every onset label marks the symptom, so the decision anchor still comes only from our interventions (R-044/R-057).
  2. Top pick: podolinsky GR00T-N1.7 LIBERO v3 (podolinsky/groot-libero-10-features-v3, podolinsky/gr00t-libero-x-features-v3). N1.7 rollouts on libero_10 and LIBERO-X, with 10 action samples per inference and a Gemini-labelled onset frame plus one of 10 failure modes per failure. The labels are VLM-only. The datasets are gated (manual approval), with no licence stated, so someone has to request access.
  3. FailTime (ProTracer; ChangUoA/FailTime, CC-BY-4.0, public): human onset labels with 50 ms agreement, on ALOHA/SO-101. Use it to adopt its onset rules and calibrate vlm_label.py.
  4. LIBERO-Recover's labels are not released (watch it). RoboFAC (roots injected, so known by construction) can test the UQ10 rules. FailGen is a protocol to port to LIBERO.
  5. The ~30-episode hand set is still needed, now as an audit of the podolinsky onsets under FailTime's rules. Public labels can't replace labels on our own libero_spatial rollouts.
