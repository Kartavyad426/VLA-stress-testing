Mining spec PoC: what each piece needs

Internal, for the user only · 2026-10-08 · PoC session · companion to the stakeholder toy (docs/MINING_SPEC_TOY.html) and to docs/MINING_SPEC_DESIGN.html §7b, which it builds on rather than repeats. V = checked against code or files in this session. I = inferred.

Bottom line. Every component of a LIBERO-only PoC on route P7a (dataset search) can be built deterministically from sim state, with no learned model or API. Most of it now exists as toy scripts (experiments/poc_toy_*.py). The work left is generalising from one task to ten, fixing two silent detector bugs, and validating root detection. My rough estimate is ~9–12 working days for P7a, including a day of labelling, plus 3–6 for sim generation (P7b) I. The toy also produced a substantive result: on the case it ran, the human demos contain no success from the failure situation, while one of our own runs does V.

2 · Corrections and additions to §7b (sent to prim)

  1. P4a is not usable as is. divergence_point reads r.series("ee_xy"). LIBERO traces have no ee_xy, and series returns [], so the function returns "trace stayed inside nominal envelope". It does this on the toy failure against both the same-start success and the nominal run, which starts 9.6 cm away. This is a silent G8 violation: the function should abstain. The fix is small (read eef_pos[:2]) but is impl's to make. V
    For start-pose roots, "nominal at the same seed" is also the wrong reference, because it starts elsewhere. The useful reference is a same-start success under another noise seed, which exists only where we ran replicates.
  2. P2a, the demo restore needs no env. Each demo's model_file MJCF loads in plain MuJoCo once two asset prefixes are remapped (the authors' paths point to local LIBERO-plus and robosuite). Setting qpos from states gives object and eef poses. obs/ee_pos[t] equals the restored grip site of states[t+1] (lag 1, max 0.6 mm). Both pools must read eef and objects from the same restored state. V
  3. P2a, orientation. Rollouts' eef_quat is not in MuJoCo's site frame: it is near identity at the start, while the site points down. Recompute gripper rotation by FK from joint_pos in one model for both pools. V
  4. P6, the evidence key. In runs/r047, rollout_id is shared across noise seeds (rows 14 and 20). Spec evidence links need (run, row) or a seed-aware id. This is the same class as the D25 join bug. V
  5. P3a and the terminal field. classify.failure_cost detects drops from a holding series that LIBERO traces lack. On the toy failure it says "benign: ended without acquiring the object", although the bowl was lifted 9.6 cm and dropped. Cost is Phase 1, but D13's terminal field needs a drop detector built from target height. V
  6. P7b, replay determinism is now shown for our LIBERO-Plus rollouts (4/4 rows, ≤ 2.6 mm). It is still not shown for libero_raw demos (D22). V
  7. P2, tolerances decide the answer. On the toy, the single hit appears at ±1.5 cm and vanishes at ±1.0 cm. Human-demo offsets reach the failure only at ±2.5 cm, and never jointly with layout. P2's default tolerances are therefore a result-determining choice, not a detail. The PoC should report the sweep with every search. V

3 · What the toy adds to each pending decision

Options and their trade-offs are in §7b. This only adds what running the toy showed.

ItemToy evidenceLeaning
P1 · ms1Option a is enough to produce a non-trivial result on one instance: the human-demo coverage gap and a found success from another start. A pass test like "≥ 1 instance yields successes meeting its criterion" was met here, but only borderline. Va. The pass test should require the tolerance sweep, so that a borderline hit isn't counted as a pass.
P2 · ms2Derived fields were enough to search both pools, and the human-readable funnel explained the empty result. The raw wrist frames of the failure and the hit look alike but not identical (the bowl appears larger in the failure: dz 1.3 vs 2.5 cm). Va now; c later, when a mechanism says vision matters.
P3 · ms3One template (grasp.lift) separated the toy cleanly: slip 2.1 cm vs success 11 cm. It also flagged a mid-episode success in the failed run (t=201), which is how the drop became visible. Va, with a drop rule added.
P4 · ms4The existing divergence detector is silently wrong on LIBERO, and the segmenter flickers (§2). The toy's root came from the criterion rule, not from divergence_point. Vb, after the fix. With today's code, a's error rate is not just unknown; it is wrong.
P5 · ms5Slip vs miss needed an explicit threshold (1.5 cm lift). The ids the toy used are placeholders. Vb, with numeric rules per mode.
P6 · ms6The toy instance is a single JSON file. The searches return event lists that would fit JSONL. The evidence key needs fixing either way. Va for specs; JSONL for the event tables behind search.
P7 · ms7Route a alone turned up one success. Route b's prerequisite (restore by replay) works for our rollouts. The same-start success shows the policy itself can be the driver from a restored root. Va for the PoC; b as the stretch, with the policy under resampled noise as the first driver.

4 · Rough total for the leaning path

P1a · P2a · P3a + drop · P4b · P5b · P6a + JSONL events · P7a, over LIBERO-Spatial's 10 tasks: root detection 2–3 d, snapshot 1.5–2 d, criteria 1–1.5 d, index 0.5–1 d, schema 1 d, search 2–3 d, plus 1 d of labelling for P4b, ≈ 9–12.5 days. P7b adds 3–6 d plus GPU. I
Risks. (1) The toy is one instance; its "human demos never cover this" finding may not hold for other scenes or roots. (2) The layout check uses world xy, so demo initial-state draws (D22: 0.08–0.16 off the eval files) can exclude demos that a relative-layout check would keep. That choice is part of P2. (3) Everything here is sim-state based. None of it transfers to image-only data without P2b. I
