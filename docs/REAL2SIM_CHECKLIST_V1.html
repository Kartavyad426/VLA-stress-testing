1 · Why a rebuild

The old checklist (10-23) judged a scene partly by replaying the real operator's motion against it (real grasp, release and scale: old 1.5–1.7). On the 10-27 scenes those checks fail for reasons unrelated to whether the scene is usable: they only fit "pick into a bowl" tasks, they compare later grasps with the objects' starting positions, and they match each grasp to the nearest sim object (so on c3 every grasp became "apple_1"). The user, 10-27: "if the scene itself is wrong, how can that motion even translate … its always gonna fail … Can we make a general scripted expert scene test?" and "we will need to rebuild the entire checklist completely".

The scene is a digital cousin, not a replica (user, 10-26: "it doesn't have to be a replica … an exact replica [isn't] even possible"). So the checklist asks two main things: does the physics hold up for every interaction, and do the images show exactly what the physics contains. How close it is to the recorded episode becomes a report (section Z).

2 · Rules every check follows

  1. Nothing gates the pipeline. Each check gives a report label (consistent / check / likely error); the user is the checker (user, 10-26).
  2. Bars come from error injection: once per rig, plus a per-scene noise floor and one positive control (SCENE_V1_MECHANISMS §17; orange results §17a). A check that misses its positive control on a scene is reported as "blind on this scene", and its labels there aren't trusted.
  3. Real images can only be compared before anything is touched. Appearance and image-physics checks (C, D) use frame 0 and the frames before the first grasp, with the sim posed at the recorded joints. After that there is no real reference.
  4. Never check a camera only from itself. Checks made from the exterior camera can't see that camera's own error along its line of sight (K11; c11: outline overlap 0.49 but table 13 cm off). Every geometry check names its independent source (wrist stereo, recorded joints).
  5. "Unwitnessed" is its own label IMAGE_PHYSICS / res32: a check whose witness skipped every frame (e.g. the orange bowl in A4: it touches the image edge in every frame, K1) reports "unwitnessed", not a pass. Different from "blind on this scene" (rule 2): measured but insensitive vs not measured at all.
  6. Detection-based checks use one counting protocol IMAGE_PHYSICS / res32: one detector call per noun (no colour words), robot pixels masked, detections assigned to sim objects by mask overlap, the protocol itself validated by injection (an object added or removed must be counted). Used by A3, A6, C2, D2.
  7. A failed check is a bug until shown otherwise (kept from the old rules).
  8. Any edit re-runs what it touches: an edit to size, mass, position or calibration re-runs the checks of its section and everything after (old 2.3).

3a · How a scene is judged: four stages (user, 10-28)

User, 10-28: "if we focus on geometry of objects with each other and then make sure that camera looks approximately similar to what was in the real video, how can we measure that texture is covering the things it should cover, and there are no ghosts in the background … if a scripted expert works can we say that its doable … for that we need to see if objects look right in exterior view … calibrating using … grasp point, this way we will have any number of accurate points". The stages run in order; each uses the checks below.

StageQuestionHow it's measuredChecks
1 · GeometryAre objects right relative to each other, the table and the robot?Placement independent of the exterior camera: grasped objects at the real fingertip of their first grasp, wrist-seen objects from wrist stereo, table height from wrist stereo. Verified by what wasn't used to place: real drops land in the containers, objects rest on the table, sizesA1, A3, A4, A5, A6, B1
2 · DoableCan the task be done in this physics?Scripted expert succeeds = doable (feasibility only; says nothing about what the policy will see)B3 (+ B4/B5 robustness), E1, E2
3 · CameraDoes the exterior view line up with the real video?Camera fitted after the scene is built, from many exact 3D ↔ 2D pairs: the real gripper in many frames of the real video (3D from the recorded joints; 2D located by clicks in the inspector or render-and-match, since the detector can't localise the gripper), plus the stage-1 objects ↔ their real masks, plus the robot outline. Then measured: sim robot over the real robot in all frames (overlap, pixel error), sim objects over their real masks at frame 0, the fitted table level. Note: the scripted expert's grasp points can't calibrate the camera, since no real image shows themA7, D1, D4
4 · AppearanceDo the images cover what they should, with no ghosts?Exterior ghosts: at frame 0, composite vs real frame; outside the sim-rendered robot and objects the background is the real image, so any difference there is a ghost (arm left in the median plate, unbuilt objects); per object: real object with no sim object over it = missing, sim object over no real one = misplaced. Wrist coverage: while the scripted expert runs, the share of the wrist view's table pixels with real texture vs filled-in, per frame and per task; flags tasks that leave the covered area. Wrist ghosts: run the detector on the wrist table texture itself; it must find no objects. Policy-relevant: image swap at a few statesC1, C2, C3, C6, D2, D3

12 · Out of scope for v1

  • Articulated objects (drawers, doors, lids) and deformables (cloth, cables): filtered at scene selection.
  • A different robot or camera rig: re-runs R entirely (next phase, user 10-26).
  • Camera moves, background and table-texture changes beyond the real pixels (would need generation; see the Cosmos discussion).
