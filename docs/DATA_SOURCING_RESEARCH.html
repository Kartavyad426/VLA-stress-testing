Sourcing demonstrations for targeted VLA fine-tuning: the start-pose case

2026-09-30 · Research note for SFT · Policy: GR00T N1.7 (nvidia/gr00t17-lerobot-libero_spatial-640) on LIBERO-Plus, 8 GB GPU · Target: the robot-initial-state perturbation · Inputs: docs/DATA_MINER_SPEC.html, docs/R056_POSTMORTEM.html, RESULTS.md R-053 → R-058 · No GPU jobs were run and nothing was committed.

Every claim carries a tag:

  • established is from a cited paper or from our own measured artifacts.
  • recommendation is my judgement.
  • hypothesis fits the evidence but has not been tested.
  • unverified means I could not check it, for example code availability or details of 2026 papers that I read only at abstract level.

0. Bottom line

  1. established Automated demo generation is a mature field. Failure-targeted data for VLAs is an active 2025–26 field.
    • MimicGen and its successors, DART, the DAgger family, CCIL and TAMP/LLM-planner data engines all generate demos automatically.
    • Several 2026 papers already follow "find failures, then synthesise data for them": VLAMotor, RECALL, FLARE, and Jung & Park on initial-pose dependence.
    • The sources we listed in the spec are not new ideas.
  2. established The closest published baseline to our S2 has already been tried on this exact perturbation, and it helped little. LIBERO-Plus built its robustness training set by executing the original LIBERO demo actions in perturbed environments and keeping the successes (>20k trajectories). On robot initial state, OpenVLA-OFT rose only from 21.7% to 30.3% (+8.6 pp), the smallest gain of any row except language and light. Replaying borrowed actions from a moved start is the same idea as S2, and it hits the same wall.
  3. recommendation Stop using S2 as the main source. Build a state-conditional source instead.
    • Option A, "bridge-and-join" (a one-skill MimicGen-lite). A privileged controller drives from the perturbed pose to a join point on a human demo's own path, then tracks the rest of that demo. The layouts come from the demos' own recorded initial states.
    • Option B is the full scripted privileged expert (S3) with DART-style noise injection.
    • Either one needs a style-alignment step (DATAFARM shows raw planner data can fail entirely), a clean-grasp gate, full episodes, and offset-stratified sampling.
  4. recommendation Cheapest discriminating experiment: a bridge-then-handback rescue. Drive only the new bridge controller for the first forward or forwards at far offsets (>12 cm), then hand back to the unmodified base, with a no-op arm at 3 seeds. It costs about 1 GPU-hour and needs no training. If the base then succeeds, the bridge labels are the right fine-tuning target. If it doesn't, even far-offset failures are not first-chunk failures, and we need whole-episode expert data (Option B).
  5. recommendation Gate data quality before any training. The gates in §4 check coverage against the eval distribution in cm, a clean-grasp definition, phase mix, dose accounting, and label consistency against the base's own predictions. Also run the post-mortem's replay-only control arm first. Without it, no data change can be attributed.

1.5 Data quality and curation (relevant to Q3)

  • established Belkhale et al., Data Quality in Imitation Learning, arXiv:2306.02437. Quality is framed as action divergence (expert vs learner at the same state) and transition diversity, and more state diversity is not always better.
  • established Demo-SCORE, arXiv:2503.03707 (code). A classifier trained on policy rollouts filters unreliable demo strategies (+15–35 pp).
  • established CUPID, arXiv:2506.19121: influence functions rank demos by their effect on closed-loop return. DataMIL, arXiv:2505.09603 (code): datamodels with a surrogate loss instead of rollouts. Both are principled, and both are costly for a 3B model on 8 GB.
Answer to Q1. established Yes, it is established. Every source in our spec has a named precedent. The one piece of prior work run on our exact perturbation, the LIBERO-Plus fine-tune, already shows that borrowed-action data barely moves the robot-initial-state row. For LIBERO the most reusable code is MimicGen plus MimicLabs, which already integrates LIBERO.

2. Q4: Is "localise the mechanism, then target the data" novel?

established The parts are all covered:

  • Finding failures and targeting data at them is covered by VLAMotor, RECALL, failure taxonomies, FLARE, and Jung & Park.
  • Interventional attribution inside VLAs is covered by:
    • Häon et al., Mechanistic interpretability for steering VLAs, arXiv:2509.00328;
    • Embodied Interpretability (ISS/NMR, interventional masking of visual regions), arXiv:2605.00321;
    • FACT (Stanford), arXiv:2608.01402. It localises contact-rich failures to the flow-matching noise schedule and fixes them in the architecture and schedule, not with data.
  • Initial-pose diagnosis that includes wrist-camera influence, followed by targeted pose augmentation, is covered by Jung & Park, arXiv:2608.11769. It is the closest single paper, and I read only its abstract.

recommendation What I did not find is this combination:

  1. a causal intervention on the policy's own inputs and time (splice-restoring the wrist camera versus the agent view, and "decided at forward k");
  2. used to set the data specification: which frames need new labels, how many forwards, and which source can produce correct labels;
  3. then checked by predicting and measuring the mechanism shift after training (W transfer 0.88 → 0.84).

That is a defensible contribution, but a narrow one. Claim it as "mechanism-specified data targeting with a pre-registered mechanism readout", not as targeted data generation in general. This rests on a search done on 2026-09-30. Before claiming novelty in writing, read Jung & Park and FLARE in full.

3. Q2: What we should source, and how each option handles failure modes 1–6

3.1 One observation from our own data

established (R-056 post-mortem §5.1) Beyond 16 cm:

  • the base policy on its own succeeds on 16 of 33 held-out starts (≈ 48%);
  • S2 minting, which drives the nominal chunk, keeps only 2 of 10 (20%).

From 12 to 16 cm they are level: base 4/12, S2 yield 0.33.

hypothesis At far offsets, the borrowed nominal chunk is worse than the policy's own first chunk. The reason: LIBERO actions are end-effector deltas, so a canonical approach executed from 16 cm away lands 16 cm off. The directions and n differ, so treat this as a hint. It matches LIBERO-Plus's small gain, and it is why I would stop investing in S2 as the main source.

3.2 Option A (recommended first): "bridge-and-join", a one-skill MimicGen-lite

recommendation For each generated demo:

  1. Layout. Reset to one of the recorded initial states of the original LIBERO-Spatial human demos, about 50 per task in the source HDF5. This gives real layout variation for free, and each layout has a matching human trajectory.
  2. Start. Apply a joint-space start perturbation. Sample it stratified by gripper offset in cm so that the kept set matches or over-covers the eval distribution: oversample 12–20 cm and use at least 4 directions per scene. Exclude the held-out set (G4).
  3. Bridge (privileged, purposeful). A controller that reads the true EEF pose issues OSC delta actions from the perturbed pose to a join point on the human demo's EEF path. The join point is the earliest approach-segment waypoint that is reachable without passing near the object. The gripper stays open. Speed and acceleration are scaled to the human demos' per-step action statistics, as DATAFARM-style alignment. Every bridge frame is a state-conditional "go to the object's path from where you are" label.
  4. Join. From the join index on, track the human demo's recorded EEF target poses (MimicGen's execution mode) rather than replaying its deltas open-loop. Residual bridge error is then corrected instead of carried along.
  5. DART option. On the bridge and approach, execute the clean action plus small noise, and record the clean action as the label. This covers near-miss states with correct labels.
  6. Record the full episode. Tag frames as bridge, join or replay. Keep an episode only if it passes the clean-demo gate in §4.2.

How it relates to the literature: this is MimicGen's "transit into the first object-centric segment" and FLARE's "bridging" for a task with a single grasp-and-place skill. On LIBERO-Spatial, one skill template covers all ten tasks.

3.3 Option B: full scripted privileged expert (S3) with DART and style alignment

recommendation A waypoint expert for the whole skill: approach, descend, close, lift, transit, descend, open. DART noise is injected on execution, and the expert's timing and speed are aligned to the human demo statistics. Use B if the cheap experiment (§5.2) shows that far-offset failures are not decided in the first forwards, so that whole-episode purposeful labels are needed. B is also the prerequisite for DAgger-style relabelling (S6) later.

Main risk: the style gap. DATAFARM measured raw planner data at 8.3% against 56.7% after alignment. The blindfolded-experts result warns that over-informed straight-line demos can clone into brittle policies. A inherits most of its motion from human demos, so it carries less of this risk.

3.4 What to keep and what to defer

  • S2 (rescue minting): keep it only as a comparison arm, and fix it first (clean filter, full episodes). The question it answers: does the source matter at a matched budget?
  • S1 (re-render): not applicable to start pose, because the start pose is physical.
  • S4 (full MimicGen port): defer. Option A is its minimal version. Port MimicGen or MimicLabs only when layout is the target.
  • S6 (DAgger): after B exists. It is iterative and GPU-hungry on 8 GB.
  • S7 (teleop): use it only for a 20–50-episode validation set.
  • RL post-training: out of reach on 8 GB for this model.

3.6 Separate the data question from the recipe question

recommendation The post-mortem found recipe drift as a live cause: an effective batch of 8 against the checkpoint's 320 at the same LR, augmentation off, and LoRA on vl_self_attention. A better data source trained with the R-056 recipe can fail again for recipe reasons. So:

  1. First run the replay-only control (post-mortem §9 B) with the corrected recipe.
  2. Then compare, at the same recipe and a matched budget: {replay only, S2 fixed, Option A}.

That three-arm comparison is also what makes the "does the source matter?" question publishable.

4. Q3: Measuring data quality before training

recommendation Every item below is CPU-only except §4.5, and each has a pass or fail threshold, so a dataset can be rejected before any GPU training. The thresholds are proposals to pre-register, not measured values.

4.1 Coverage against the eval distribution

  • Per-band counts in cm, not requested radius, since the achieved radius is 0.74–0.78 of the request and direction changes cm offset 2×. Use the bands 0–5, 5–8, 8–12, 12–16 and >16 cm, per scene. Pass: at least 10 kept demos in every band where the eval has starts, and the kept share per band ≥ the eval share for bands beyond 8 cm.
  • Distribution distance. Report the Wasserstein-1 distance between the kept and eval gripper-offset distributions, and the same for direction (the angle between unit displacement vectors). Pass: W1 ≤ 2 cm.
  • Nearest-demo distance. For each eval start, compute the distance to the nearest kept demo start in the same scene, in EEF position (cm) plus the joint-config L2. Report the median and p90, and the fraction of eval starts with a demo within 3 cm. The post-mortem already showed success tracks this (near 28/36 against far 16/36), so it is the most predictive single number. Pass: p90 ≤ 5 cm.
  • Yield by band is recorded as a selection-bias warning. Flag any band with yield < 0.5, because there the kept set is a biased sample of the easier directions.
  • Layout coverage. Count distinct (task, initial-state or env seed) pairs. Pass: at least 10 per task, with eval layouts held out.

4.2 A "clean demo" definition (automated, from privileged state)

  1. Success, reached within the eval horizon.
  2. Exactly one gripper close before the first lift. The first lift means the object's z rises by more than 2 cm while it is in contact with the gripper.
  3. The close height is inside the human band: the EEF-minus-object dz at the close lies within the human demos' p5–p95. Compute that band from the HDF5. Minted clean demos closed at 3.4 cm and bad ones at 5.7 cm, so the band will separate them.
  4. No reopen before the place, and no more than 2 gripper-command transitions in total.
  5. No non-target contact over a force threshold, and no joint-limit hits.
  6. No stall: EEF speed stays above ε for at most k consecutive steps, for example 20.
  7. Length ≤ the human p95 for the task. Never truncate inside a phase.

Report the reject rate per rule. The rules are privileged-state checks on generated data only, so they don't leak into policy inputs.

4.3 Phase mix and gripper prior

Segment by gripper state and object height into approach, grasp, lift/transport, place and release. Pass: the phase shares of the training mix (after the replay blend and sampling weights) are within ±10 pp of the base's original training data, except for the phases deliberately up-weighted, which are declared. In particular, compare the closed-gripper frame share with the replay set's 54%. The pilot's 31% was flagged as a possible cause of gripper cycling.

4.4 Dose accounting (from the sampler, before training)

For each frame class (bridge/driven frame 0, other bridge frames, post-join, replay), report the share of draws and the expected views per frame at the planned number of optimiser steps and effective batch. Pass: every "new-signal" frame is seen at least 5 times in expectation, and new-signal frames are 25–50% of draws. R-056 reached 0.42–0.83 views.

4.5 Label consistency (one cheap GPU inference pass, no training)

  • Action divergence against the base, after Belkhale et al. Run the base policy on a subsample of generated frames and measure ‖base chunk − label chunk‖. Expect it to be high on bridge frames, where the new signal is, and at the noise floor on post-join and replay frames. Measure the noise floor as the base's own chunk-to-chunk variability across flow seeds. A post-join frame far above the floor means that source disagrees with the base, which risks two modes. The fraction of frames above the floor is the true "effective dose".
  • Cross-source contradiction. For near-duplicate observations (kNN in proprio plus frozen VLM embedding) from different sources, compare the labels. Flag clusters whose label spread is more than 2× the within-source spread.
  • Style statistics against human demos, as DATAFARM alignment. Compare per-dimension action mean and std, speed profile, jerk, and time-to-grasp. Pass: each is within the human p5–p95 envelope.
  • Round trip (G6). The converted dataset replays in sim to the same outcome, and the action range and normalisation stats are unchanged (G1).

Optional later: a CUPID or DataMIL influence ranking. It is the principled answer to "which demos help", but costly for a 3B model on 8 GB. A Demo-SCORE classifier on rollouts is a cheaper proxy.

5.2 The cheapest discriminating experiment: a bridge-then-handback rescue (no training)

Build only the bridge controller (about 1 day, CPU-testable). Then run two checks.

  1. CPU: generator yield. Run bridge-and-join with no policy on about 60 non-held-out starts across the offset bands. Pass if clean yield is ≥ 0.7 in every band, including >16 cm. This tells us whether Option A fixes coverage at all.
  2. GPU, about 1 hour: rescue with a state-conditional correction. Use about 30 non-held-out starts beyond 12 cm at 3 noise seeds. Arms:
    • P: a no-op re-run;
    • B1: bridge drives forward 0 only, then hand back to the unmodified base;
    • B*: bridge drives until the join, then hand back.
    This is the R-044 design with a state-conditional correction replacing the nominal chunk, and it reuses the splice's drive-then-handback machinery. Report flips against P and the post-hand-back gap.

How to read it.

  • If B1 or B* rescues far starts well above P, far failures are still "decided early". The bridge labels are then a correct target, and the policy only has to learn to emit them, so go with Option A.
  • If even B* fails, the base cannot finish from a good pose at far offsets. Whole-episode labels are needed, so go with Option B, and S2-style sources are ruled out for this band.
  • If P already succeeds at the rate B* does, far-offset failures are render jitter, and no data source will show a gain at this eval size.

Either way, it costs about a day plus one GPU-hour, and it decides between A, B and "stop".

6. Limits of this note

  • I read the 2026 papers (FLARE, Jung & Park, VLAMotor, RECALL, DATAFARM, MAGMA-GEN, STRONG-VLA, Embodied Interpretability) at abstract or summary level. Their exact methods, numbers and code status need a full read before we cite them in anything external.
  • I confirmed code availability only where a repository link is given above. Where it says unverified, I found no repository in this search.
  • The LIBERO-Plus numbers (21.7 → 30.3%) are for OpenVLA-OFT, not GR00T.
